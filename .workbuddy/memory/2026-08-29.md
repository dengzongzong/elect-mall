## 商城前端「全部产品分类」下拉整片高亮修复

### 现象
鼠标 hover 到「全部产品分类」的一级分类，下拉菜单里**多行/整片文字变红**（同时 active），而不是只高亮当前行。

### 根因
生产链路实际由 `crmeb/public/router.php` → `crmeb/public/adapter.php` 处理（绕过 CRMEB 框架）。`adapter.php` 的 `GET product/categories` 接口：
- 二级、三级 `id` 已做了 `(string)` 转换；
- 一级 `id` 漏了转换，以 19 位数字输出。

JS `Number.MAX_SAFE_INTEGER` 只有 16 位，前端 `JSON.parse` 后 10 个一级分类的 id 被精度丢失，只剩 2 个不同值（其中 9 个分类共用同一个 number），导致 `activeL1Id === cat.id` 同时命中多行，整片变红。

### 修复
只改 `crmeb/public/adapter.php`：
- `GET product/categories`：一级分类输出时 `id` 强制 `(string)`；
- `GET product/categories/tree`：tree 构建前也把 `id` 强制 `(string)`（同类隐患）。

`crmeb/app/api/controller/adapter/ProductController.php` 是死代码（被 router.php 绕过），先误改后已回滚。

### 验证
- 后端接口：`/api/adapter/product/categories` 一级 id 现均为字符串，10 个分类 10 个唯一 id；
- 浏览器实测（Playwright）：10 个一级分类逐行 hover，每次只有 1 行高亮；
- 点击「噪音滤波器」跳转 URL 包含完整 19 位 id：`#/category/2092951330683498655`，不再是精度丢失后的错误 id。

## 统一 Element Plus 组件字体为鸿蒙黑体

### 背景
商城主字体 HarmonyOS Sans SC（`App.vue` @font-face，public/fonts 下 3 个 woff2 各约 4.4MB），但 `.el-button`、`.el-input__inner` 实际渲染为 Arial。

### 根因（易踩坑）
Chrome 对 `button`/`input`/`textarea`/`select` 有 UA 默认字体（Arial），**不继承 body 的 font-family**；Element Plus 也未给 `.el-button` 设置 font-family。因此**仅覆盖 `--el-font-family` 变量无效**。

### 修复（`mall-web/src/App.vue`）
1. `:root` 增加 `--el-font-family`（使 Element Plus 的 div 类组件统一字体）；
2. 新增全局规则（关键）：
```css
button, input, textarea, select { font-family: inherit; }
```

### 验证
Playwright 实测 `.el-button`、`.el-input__inner`、body 的 font-family 均为 `"HarmonyOS Sans", "PingFang SC", ...`，字体加载状态 true。

## 后台分类管理三项修复（admin-web + 后端）

### 1. 富文本编辑区太小
- 根因：`Category.vue` 的 scoped 样式写的是 `:deep(.quill .ql-editor)`，但 **`.rich-editor` 与 Quill 的 `.quill` 是同一个元素**（class 合并到组件根），该选择器要求 `.quill` 是其后代 → **永远匹配不到**，`min-height` 从未生效，实测编辑区只有 **114px**。
- 修复：改为 `:deep(.ql-container)` / `:deep(.ql-editor)`，编辑区固定 **520px**，对话框 860 → 960px。

### 2. 不同分类的编辑器内容串扰
- `QuillEditor` 加 `:key="editorKey"`，每次打开详情对话框 `editorKey++` 强制重建实例。
- 实测：在 A 分类输入标记文本后关闭，打开 B 分类内容为空、无残留。

### 3. 子类编辑详情后被挂到顶层（丢失父节点）
- 根因：后端 `PUT category/update` 是**全字段覆盖**，`$data['parentId'] ?? ... ?? 0`，而后台「编辑详情」只提交 `{id, name, description}` → `parent_id` 被写成 0。
- 修复（双保险）：
  1. `adapter.php` 改为**只更新请求中显式传入的字段**（列名走白名单常量，无注入风险）；
  2. 前端 `descForm` 携带 `parentId/prefix/sort/status`，并新增「分类层级」展示。
